# 课表课程维护与视觉优化设计

## 目标与范围

在不改变现有 PDF 导入、学期、节次设置、节假日/调休映射及已存课程数据的前提下，给当前学期的课表增加直接维护课程的能力：新增、编辑、删除、严格冲突校验，以及课程块的信息和颜色优化。

手动变更课程必须同步更新已有的课程提醒。当前项目的课程提醒实现为 Android 系统日历的提醒/通知，不另新增一套课程精确闹钟；手动维护沿用这一既有渠道。课程数据库是事实来源；系统日历是 Android 的外部系统，无法参与 Room 事务。同步失败时保留已保存的课程，并明确提示“课程已保存，提醒同步失败”，同时提供重试，避免让用户误以为课程没有保存。

本次不新增数据库表、不创建独立的手动课程类型，也不改变导入流程。

## 现有基础与边界

`CourseEntity` 已保存课程名称、学期、星期、起止节次、原始周次规则、解析后的周次、地点、教师与备注；`course_weeks` 保存规范化周次。现有导入链路已经使用这些数据并负责安排课程提醒。

手动维护复用同一实体和同一周次表。所有操作限定在当前学期；学期缺失时，课表继续展示现有导入引导，不提供手动新增入口。

## 界面与交互

### 课表格

- 连续节次课程继续渲染为一张完整课程卡。
- 点击课程卡打开居中的 Material `AlertDialog` 编辑框，而不是底部抽屉；原课程字段全部预填，保存时保留课程 ID。
- 点击任一空白节次单元格打开同样的居中新增框，默认带入当前星期与开始节次，结束节次默认等于开始节次。
- 网格的竖向滚动优先；只在空白格短按时发起新增，不为滚动手势新增课程。
- 删除仅出现在编辑框内。点击删除后显示第二个确认框，文案包含课程名称，确认按钮采用弱危险色；取消不改变数据。

### 编辑字段

必填字段：课程名称、星期、开始节次、结束节次、周次规则。

可选字段：地点、教师、备注；保留现有实体的其他非本次编辑字段。

周次规则使用已有文本语法和解析器，例如 `1-16周`、`1-16周 单周`、`2,4,6周`。保存前必须解析出至少一个有效周次，并且开始节次不得大于结束节次。

### 课程卡信息与颜色

课程卡常驻两行信息：课程名在上，地点在下；教师不再常驻显示，但在编辑框内保留。课程名使用约 13–14sp、600 字重；地点使用约 12–13sp、600 字重并和标题保持明显间距。

颜色只由星期决定，跨周稳定：

| 星期 | 背景 | 文字/强调 |
| --- | --- | --- |
| 周一、周五 | `#EDE9FF` | `#7464D9` |
| 周二、周六 | `#E6F5EE` | `#579B78` |
| 周三、周日 | `#FCE8EF` | `#D96B91` |
| 周四 | `#E5F3F6` | `#5C9CA8` |

## 数据流与一致性

1. `TimetableScreen` 维护新增/编辑/删除确认的临时界面状态，并将用户意图传给 `TimetableViewModel`。
2. `TimetableViewModel` 将表单转换为课程输入并调用仓库；界面不直接写数据库。
3. 仓库验证字段与周次规则，读取当前学期所有课程，执行冲突判断。
4. 无冲突时，在同一数据库事务中插入或更新 `CourseEntity`，并替换该课程的 `course_weeks`；删除课程时一并清理该课程的周次行。
5. 事务成功后由同一仓库同步既有系统日历课程提醒：新增创建未来提醒，编辑清理该课程旧提醒并按新课程重建，删除清理该课程提醒。
6. 系统日历同步失败不回滚课程事务（外部日历操作不能可靠回滚）；界面显示“课程已保存，提醒同步失败”，提供重试入口，并保留同步链接以便重试清理或更新。
7. 成功后 Flow 自动刷新当前课表，不需要重新进入页面或重新导入。

## 冲突规则

候选课程与已有课程发生冲突，当且仅当：

1. 属于同一学期；
2. `dayOfWeek` 相同；
3. 解析后的周次集合存在交集；
4. 节次区间相交，即 `candidate.startPeriod <= existing.endPeriod` 且 `existing.startPeriod <= candidate.endPeriod`。

编辑课程时，检查中排除与候选课程相同的 ID。发生冲突时不写入，错误消息须至少包含冲突课程名称和冲突星期/节次。不同周次、不同星期或相邻不重叠节次允许保存。

## 模块改动

- `TimetableModels.kt`：新增手动课程表单、编辑状态和保存结果所需的 UI 模型，不修改数据库实体。
- `TimetableRepository.kt`：在现有接口与 Room 实现中增加手动新增、更新、删除课程的原子操作；复用周次解析、Room DAO 与提醒同步策略。
- `TimetableViewModel.kt`：管理表单、校验错误、保存/删除事件和异步状态。
- `TimetableScreen.kt`：增加空格点击、新增/编辑居中对话框、删除确认框、两行课程卡信息和稳定的四色映射。
- `DailyNavHost.kt`：传递新增的课表事件回调。
- 仅在确有必要时扩展 `CourseDao`，优先复用其现有按学期查询、更新和课程周次删除接口。

## 错误处理

- 表单缺少必填项、周次无法解析、无有效周次、星期或节次越界、结束节次早于开始节次：阻止保存并在表单内说明原因。
- 时间冲突：阻止保存并显示冲突课程名称和时段。
- 当前没有学期：不展示课程维护入口。
- 提醒同步异常或权限不足：课程仍按已验证输入保存，明确提示提醒尚未同步并提供重试；不得显示为“保存失败”。

## 验证方案

新增或扩展单元/仓库测试，覆盖：

1. 空白格新增的默认星期、起止节次；编辑保留原 ID 和已有可选字段。
2. 周次解析、字段校验与无有效周次的错误。
3. 同星期、同周次、重叠节次被拒绝；不同周次、不同星期、相邻节次允许；编辑排除自身。
4. 新增、编辑、删除后 `course_weeks` 被正确写入或清除。
5. 新增、编辑、删除分别建立、重建和清理既有系统日历课程提醒；同步失败时课程数据保留，并报告可重试的提醒同步状态。
6. 课程块仅呈现课程名与地点，星期颜色映射为周一至周日的 `紫、绿、粉、蓝、紫、绿、粉`。
7. 回归课表导入、调休映射、节次设置和既有课表测试。

## 非目标

- 不改课程 PDF 解析规则、导入预览、替换导入策略或学期切换。
- 不新增批量编辑、拖拽排课、跨学期复制、课程分类或新的日历数据源。
- 不改变节假日与调休的课程显示/映射规则。
