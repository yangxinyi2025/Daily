# Daily 经期记录与课程提醒设计

## 目标

完成四项相互关联的改动：

1. 将健康页的活动/步数读取替换为经期记录。
2. 缩紧课表左侧节次时间栏，将每节显示为节次、开始时间、结束时间三行。
3. 为课程建立可配置、可后台投递的课前提醒。
4. 修复日程消息提醒未可靠投递的问题。

## 健康：经期记录

### 用户体验

健康页面保留体重与月报入口，将“活动”替换为“经期”。经期页显示：

- 最近一次经期的开始日和结束日；
- 下一次预计开始日；
- 新增、编辑、删除经期记录。

记录只包含开始日和结束日。默认周期为 30 天；设置页允许修改周期天数。预测规则为最近一次开始日加周期天数。未有记录时不显示预测，改为引导添加第一条记录。

### 数据与迁移

- 新增 `period_records` 表：`id`、`startDate`、`endDate`、`createdAt`、`updatedAt`。
- 数据库升级至 version 4，新增迁移并保留现有体重与历史活动数据，避免删除用户本地资料。
- 健康状态、仓库与页面不再创建 Health Connect 或手机传感器适配器；移除健康数据读取按钮、状态信息及不再需要的健康/活动识别权限请求。
- 月报保留为体重月报，不再展示步数相关文案。

## 课表时间栏

每个节次使用三行紧凑排版，例如：

```
1
08:00
08:45
```

时间栏宽度按三行时间缩小，其余七天课程列获得更多空间。12 节课的时间仍严格采用用户提供的时间表。

## 课程课前提醒

### 配置层级

设置页新增“课前提醒”：关闭、提前 5/10/15/20/30 分钟和自定义分钟。该值是全局默认。

每门课程详情提供三个选择：

- 跟随全局；
- 关闭；
- 单独提前指定分钟。

课程字段增加可空覆盖值：`null` 表示跟随全局，关闭与分钟数使用明确枚举/值编码，避免把关闭误当成 0 分钟提醒。

### 调度

当前 `scheduleCourseReminders` 仅有空实现，课程导入后实际上没有向 Android 登记任何提醒。本次将它替换为真实实现：

1. 从课程、周次、学期开始日和节次时间生成每一节课的实际日期时间。
2. 只保留未来提醒；按课程、周次、开始时间生成稳定且唯一的请求标识。
3. 使用 `AlarmManager.setExactAndAllowWhileIdle` 登记消息提醒。
4. 重新导入课表、修改全局默认或修改单门课程覆盖值后，先取消受影响旧提醒，再重新登记。
5. 开机、时区变化、时间调整和应用更新后重建未来的日程与课程提醒。

## 日程消息提醒可靠性

普通日程消息与闹钟共享可靠性原则：要按时在后台投递，必须具备通知权限与精确闹钟特殊权限。若任一权限缺失，日程保存成功但界面会明确显示“未登记后台提醒”，并提供直接前往系统授权页的操作；不再静默采用可能被系统延迟的降级方案。

调度器在每次保存后返回实际登记结果，UI 显示已登记的触发时间。测试会验证：

- 未来的消息日程出现在系统 `dumpsys alarm`；
- 退到后台后接收器投递通知；
- 缺少任一必要权限时不会显示“提醒已设置”。

Android 强制停止应用会取消所有应用闹钟，这是系统限制；正常退到后台不受影响。

## 测试与验收

- 经期：周期预测、日期校验、数据库迁移、编辑删除。
- 课表：12 节三行时间显示、全局提醒、单课覆盖、导入后生成正确触发时间。
- 日程：权限受限状态与未来消息登记。
- 模拟器：安装新版，验证课表界面、创建未来提醒后退到后台，检查系统通知和日志；健康页不再请求 Health Connect。
