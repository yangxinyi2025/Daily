# Daily 系统日历提醒同步设计

## 目标

让 Daily 中带有明确日期的日程和课程提醒，交由手机系统日历的提醒能力执行。Daily 继续作为唯一的编辑界面；系统日历负责锁屏展示、通知声音和振动。

这项调整针对 iQOO 13 / Android 16 上第三方应用的后台提醒限制：此前 Daily 可以登记并在部分场景收到到点广播，但无法稳定地在锁屏状态展示或响铃。系统日历已由用户实机验证在该手机上正常工作。

## 范围与边界

- 覆盖普通日程、生日等年度重复日程，以及课程的每一个实际授课周次。
- 同步的提醒时间与 Daily 当前的“提前 X 分钟”设置一致。
- 系统日历的 `METHOD_ALERT` 提醒是本次唯一的锁屏消息执行者；同步成功后，Daily 不再为同一条内容登记本地后台通知或闹钟，避免重复提醒。
- 系统日历负责最终的显示方式、声音和振动；Daily 不承诺将普通日程强制做成全屏闹钟页。
- 不把任意日期的日程交给系统时钟。Android 的 `ACTION_SET_ALARM` 只支持时刻和可选重复星期，不能指定日期；这样做会造成未来日程提前响起。

## 权限与首次启用

1. 在用户首次保存含提醒的日程或启用课程课前提醒时，Daily 请求 `READ_CALENDAR` 和 `WRITE_CALENDAR` 运行时权限。
2. 获准后，查询可写日历，优先选择主日历；没有主日历时选择第一个可写且可见的日历。
3. 没有可写日历、权限被拒绝或日历 Provider 写入失败时，Daily 保留本地数据，显示明确失败原因，不把该条标记为已同步，也不显示“提醒已成功”。

## 数据模型

新增内部同步映射表，每条记录包含：

- 本地对象类型：`SCHEDULE_EVENT` 或 `COURSE_OCCURRENCE`。
- 本地对象 ID：日程 ID，或课程 ID 加周次组成的稳定标识。
- 系统日历 ID 与系统事件 ID。
- 事件开始时间，用于在课程/学期变化后识别过期映射。
- 同步状态与最近失败信息。

映射表只保存 Daily 创建的事件，绝不修改或删除用户手动创建的系统日历事件。

## 同步流程

### 普通日程

1. Daily 保存本地日程。
2. 若已授予日历权限，创建或更新标题为 `Daily｜<日程标题>` 的系统日历事件。
3. 事件包含准确的开始、结束（默认开始后 30 分钟）、时区与备注。
4. 写入一个 `METHOD_ALERT` 提醒，分钟数等于 Daily 的提前提醒分钟数。
5. 保存或更新映射。编辑日程时更新同一系统事件；删除日程时删除同一系统事件。

年度重复日程使用系统日历的年度重复规则；若所选日历不支持该规则，则只同步下一次发生时间，并明确标记为受限。

### 课程提醒

1. 根据当前学期开始日期、课程周次、星期和节次，生成每个实际授课日期。
2. 对每个未来授课日期创建一个 `Daily｜课程：<课程名>` 系统日历事件。
3. 写入用户设置的课前分钟数作为 `METHOD_ALERT` 提醒。
4. 课程、周次、学期或提前分钟数变更时，删除对应旧事件，再写入新的未来事件。

## 失败处理与可见性

- 权限拒绝：保存本地内容，并提示“未授权系统日历，锁屏提醒不会由日历执行”。
- 无可写日历：提示“没有可写的系统日历，请先在手机日历中创建或登录一个日历”。
- 写入失败：显示“系统日历同步失败”，在设置中保留最近一次错误摘要和“重新同步未来提醒”操作。
- 同步成功：日程保存提示为“日程已保存，已同步至系统日历”。
- 每个事件在同步成功前，Daily 不能声称系统提醒已生效。

## 测试与验收

单元测试：

- 选择可写主日历与无主日历回退。
- 日程创建、编辑、删除会创建、更新、删除同一个外部事件。
- 提前分钟数准确写入 `METHOD_ALERT`。
- 课程只为未来实际周次创建事件，变更后清理旧映射。
- 权限拒绝、无日历和 Provider 异常均返回明确失败状态，且不删除 Daily 本地数据。

人工验收（iQOO 13）：

1. 授予日历权限，创建 10 分钟后的日程并设提前 1 分钟。
2. 在系统日历中确认出现 `Daily｜` 前缀的事件和提醒。
3. 回到桌面并锁屏，确认系统日历在预定时间按本机设置显示提醒、震动或响铃。
4. 编辑和删除该日程，确认系统日历中的对应事件同步变化。
5. 为一门课程启用课前提醒，确认每一个未来实际周次各有一个系统日历事件，且没有重复。
