# 健康页小羊主题重构设计

## 目标与范围

将健康首页重构为与首页和已统一底部导航一致的浅青绿、浅米白、深墨绿小羊视觉体系。首页只呈现两个核心领域：体重概况与经期概况。

本改版仅变更健康首页的 Compose 结构、展示文案、局部视觉资源和对应展示测试。现有体重记录、目标体重、经期记录、周期预测、历史记录、Room 数据库、DataStore 偏好和底部导航均保持原有实现与存储方式。

不新增 BMI、健康评分、经期医疗判断或新的周期预测算法。

## 已确认的现状

- `HealthViewModel` 已实时收集体重记录、目标体重、经期记录、预计下次经期和周期天数；保存后 Flow 会自动刷新首页状态。
- `HealthRepository` 管理体重与目标体重；`PeriodRepository` 管理经期记录，并复用 `PeriodPredictionCalculator` 提供预计日期。
- `HealthDashboardScreen` 已持有体重、目标体重、经期三个现有底部编辑器；改版继续调用这些编辑器，不创建替代数据流程。
- `DailyBottomBar` 已是统一导航，健康页只继续由 `DailyNavHost` 的 Scaffold 承载，不复制底部导航。
- 项目已有抱爱心小羊资源 `health_header_sheep`；本次补齐参考图需要的透明背景趴着小羊、体重秤、靶心与橙色日历插画。

## 页面组成

`HealthDashboardScreen` 调整为以下顺序：

1. `HealthHeader`：标题“健康”、副标题、抱爱心小羊、两个小爱心装饰和“历史记录”胶囊入口。
2. `WeightOverviewCard`：绿色标题竖条、编辑入口、当前体重与目标体重双栏、内部体重趋势区与 7/30/90 天切换。
3. `PeriodOverviewCard`：橙色标题竖条、编辑入口、上次经期与预计经期双栏、底部距离下次经期区域及趴着小羊装饰。
4. `HealthHistoryScreen`：由顶部“历史记录”入口打开的健康模块内全屏历史视图，复用原有体重/经期列表、经期编辑与删除能力。
5. 原有底部编辑 Sheet：仅在用户点击入口时展示，不插入首页列表。

首页不再直接展示旧版月度四宫格、快捷记录卡、独立目标卡、独立经期卡或历史列表卡。

## 数据展示与状态

所有关键数据从现有 `HealthState` 推导：

- 当前体重：取记录时间最新的一条 `WeightRecord`；没有数据时显示“尚未记录”。
- 目标体重：使用 `targetWeightJin`；没有数据时显示“尚未设置”。
- 体重趋势：按设备时区把记录映射为日期并筛选近 7、30 或 90 天。少于两条有效记录时显示说明；至少两条时复用现有 Canvas 图表，以绿色折线与圆点绘制。
- 上次经期：取开始日期最新的 `PeriodRecord`，按项目既有 `M月d日` 规则展示；没有数据时显示“尚未记录”。
- 预计经期：直接使用 `nextPeriodStart`；没有预测值时显示“尚未预测”。
- 距离下次经期：以注入/系统日期与 `nextPeriodStart` 计算整天差。没有预测时展示“-- 天”。负数不作为倒计时展示，改为 0 天，避免出现过期天数。

加载、空、已加载和错误状态不相互混淆：真实无数据展示空文案，已有 `errorMessage` 使用现有错误提示区域，保存中的交互继续依赖现有 Sheet 提交过程与状态更新。

## 交互映射

- 点击当前体重、体重卡“编辑”或空状态，打开现有 `HealthSheet.Weight`。
- 点击目标体重，打开现有 `HealthSheet.Target`。
- 点击上次经期、预计经期或经期卡“编辑”，打开现有 `HealthSheet.Period`。
- 点击“历史记录”在健康模块内打开全屏 `HealthHistoryScreen`，复用既有历史数据、经期编辑和删除入口；不创建数据库或新的应用级导航目的地。
- 点击 7/30/90 天范围只更新本地展示状态，不写入数据库。

## 视觉与资源规范

- 页面背景 `#F6F8E7`，主卡 `#F9F7EE`，主文字 `#204A0A`。
- 体重使用绿色体系，主强调 `#B1D685`；经期使用橙色体系，主强调 `#FFB246`。紫色不作为健康页主色，蓝色不作强调色。
- 所有首页大卡采用大圆角、轻描边、极轻阴影和宽松留白，不使用渐变、玻璃拟态或工业细线图标。
- 新增素材为透明背景的圆润 3D 小羊/图标，输出到 Android drawable 资源目录，并以固定、小尺寸装饰方式放置，不能遮挡数据文字。
- 字体沿用项目已配置的圆润中文字体与首页权重体系；标题使用粗体，说明文字使用中等对比的墨绿色。

## 组件边界

- `HealthDashboardScreen` 负责拼装 UI 状态与底部 Sheet 可见性。
- 新增/调整的可组合组件仅接收显示数据与事件回调，不能直接访问数据库或 DataStore。
- 展示计算放在 `HealthPresentation.kt` 或独立纯 Kotlin 展示模型中，以便单元测试日期、文案和趋势范围。
- `HealthViewModel`、仓储、预测逻辑和 `DailyNavHost` 的数据注入维持不变，除非为历史入口增加纯 UI 状态回调所必需。

## 测试与验收

新增或更新纯 Kotlin 测试，覆盖：

- 新首页组件顺序仅含 Header、体重概况与经期概况。
- 当前/目标体重、上次/预计经期的空与已记录展示。
- 7、30、90 天趋势筛选边界与默认 30 天。
- 预计日期到倒计时天数的时区/过期边界。
- 保存体重、目标体重和经期后已有 Flow 驱动的状态刷新不回归。

完成后运行健康模块相关单元测试、Debug APK 构建，并在 Android 模拟器截取健康页空状态与含数据状态截图，对照用户提供的最终参考图检查颜色、字号、圆角、插画比例、入口与健康 Tab 选中态。

## 非目标

- 不修改已完成的底部导航外观或其它 Tab 行为。
- 不迁移或删除历史数据。
- 不改变体重单位存储、经期周期设置或预测算法。
- 不把参考图中的样例体重、日期、趋势当作真实数据写入应用。
