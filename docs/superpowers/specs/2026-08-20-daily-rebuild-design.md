## 2. 目标与非目标

### 2.1 目标

交付一个可直接安装的、中文优先、无广告、离线可用的个人生活管理 Android 应用，包含：首页、课表、日程、健康、账单五个页面，以及课表、日程、健康、账单四大功能模块。

核心数据默认保存在本机。网络能力用于可选的 DeepSeek 月度建议和 Nutstore WebDAV 备份/同步；网络不可用时，核心记录、查看、编辑和统计仍然可以使用。

### 2.2 非目标

- 不恢复或复制旧 APK 的内部源码、数据库或专有实现。
- 不将静态 HTML 放进 WebView 作为最终 UI。
- 第一版不做账号体系、多人协作、公开社区或服务端业务数据库。
- 不添加广告、行为画像或与核心功能无关的第三方统计 SDK。
- 不把 DeepSeek 或 WebDAV 设置为启动应用的必要条件。
- 不承诺旧包名 `com.yangxinyi.life` 的应用数据自动迁移；如后续确有需要，另行设计备份导入。

## 3. 产品原则

1. **本地优先**：记录和查看不依赖网络，导入文件后先在本机预览和确认。
2. **可解释**：解析失败、权限缺失、同步失败和提醒受限时，给出中文原因和下一步操作。
3. **低打扰**：只有用户主动开启的提醒和后台工作才运行；健康数据不在启动阶段强行初始化。
4. **隐私优先**：API Key、WebDAV 密码等秘密使用 Android Keystore 保护，不写入普通日志。
5. **视觉一致**：五个页面共用 Quiet Sky Unified 的颜色、圆角、卡片、间距和文字层级。
6. **可替换**：健康数据源、AI 建议服务、同步服务和文件解析器均通过接口隔离，便于测试和替换。

## 4. 视觉与页面设计

### 4.1 UI 实现方式

最终 UI 使用 Kotlin + Jetpack Compose + Material 3 原生实现。静态 HTML 原型只作为视觉参考，不直接复用 DOM、CSS 或 WebView。

统一设计系统放在 `core/designsystem`，提供颜色、字体、圆角、阴影、间距、按钮、卡片、标签、空状态、错误状态和底部导航等组件。页面只组合这些组件，并保持状态和业务逻辑与 UI 分离。

### 4.2 Quiet Sky Unified 视觉基线

原型采用浅色、留白充足、圆角卡片和低对比阴影的风格。Android 侧以以下值建立可调整的 design tokens：

| 类别 | 基线 |
| --- | --- |
| 页面背景 | `#F7FAFF` / `#F6F8FD` |
| 主文字 | `#111A32` / `#15203D` |
| 主蓝 | `#5E8CFF` / `#6F8FF4` |
| 青绿色 | `#76B8C7` |
| 成功绿色 | `#6DA987` |
| 淡紫色 | `#9188E8` / `#9E96EE` |
| 柔和玫瑰色 | `#D9909C` / `#E89AA7` |
| 主要圆角 | 16dp、22dp、26dp、28dp |
| 阴影 | 白色卡片上的轻量低扩散阴影 |
| 字体 | 系统中文字体，优先使用 Android 默认 sans-serif 与系统中文 fallback |

这些值是第一版的视觉基线，不妨碍后续根据真实设备截图进行微调。暗色主题不纳入第一版验收范围。

### 4.3 五个页面

所有主页面共享底部导航：首页、课表、日程、健康、账单。页面切换不丢失已输入但未提交的内容；返回行为遵循 Android 导航栈。

#### 首页

首页是当天概览，不重复承载完整编辑流程。包含：问候语与日期、今日课程数量和下一节课、近期日程、体重/活动摘要、当月账单与预算、今日待办或提醒入口，以及进入设置的入口。

空数据时显示可操作的引导卡片，例如“导入第一份课表”“记录今天体重”“添加日程”“导入账单”，而不是展示错误的零值信息。

#### 课表

包含周切换、当前周标识、周视图课程网格、课程详情和导入入口。导入流程为“选择 PDF → 解析 → 预览 → 用户确认 → 保存”，不允许解析结果未经确认直接覆盖已有课表。

#### 日程

包含月/周/日视图切换、日期选择、时间线、创建日程入口和快捷创建入口。快捷类型为考试、生日、小事。事件支持标题、日期、时间、提醒提前量、消息提醒或闹钟提醒；生日支持按年重复。

#### 健康

包含月切换、体重/活动/报告分区。支持记录斤为单位的体重和目标体重，展示最近 30 天体重折线、步行/跑步活动摘要、手机健康数据读取入口、月度报告和月末反馈。健康数据权限与数据源初始化只在用户进入相关功能或点击读取时发生。

#### 账单

包含月/周/年统计切换、日期范围、账单数量、预算进度、分类支出、总支出和最近账单。支持微信、支付宝 CSV/Excel 导入，解析后预览和确认；支持单笔编辑、分类、收入/支出筛选、搜索和月度预算阈值提醒。

## 5. 技术架构

### 5.1 技术选型

- Kotlin。
- Jetpack Compose 与 Material 3。
- Room：本地结构化数据。
- DataStore：非敏感偏好设置和轻量配置。
- Android Keystore：DeepSeek Key、WebDAV 密码等秘密。
- AlarmManager：需要准时触发的用户提醒。
- WorkManager：可延迟的同步、月度报告计算和重试任务。
- Health Connect 与设备传感器适配器：健康数据来源。
- PDFBox 或等价的本地 PDF 解析组件：课表 PDF。
- Apache POI 与 OpenCSV 或等价的本地解析组件：账单 Excel/CSV。
- OkHttp：可选的 DeepSeek 和 WebDAV 网络访问。

### 5.2 工程结构

第一阶段使用单一 Android app module，先以清晰的 feature/core 边界保证可维护性，避免过早拆分多模块。

```text
com.daily.life
├── core.database
├── core.datastore
├── core.notification
├── core.sync
├── core.security
├── core.designsystem
├── feature.home
├── feature.timetable
├── feature.schedule
├── feature.health
├── feature.bill
└── feature.settings
```

页面通过共享的应用状态和各自的 ViewModel 访问 repository。repository 负责组合 Room、DataStore、系统 API 和远程适配器；Composable 不直接操作数据库或网络。

### 5.3 应用身份与兼容策略

- 显示名称：`Daily`。
- `applicationId`：`com.daily.life`。
- 新工程使用新的签名身份；调试包可直接安装，发布包需要单独的 release keystore。
- 首版版本号从 `0.1.0` 开始。
- 旧 APK 的包名是 `com.yangxinyi.life`，因此系统把它视为另一个应用。旧数据不自动出现于 Daily 中。

## 6. 数据模型

所有金额以分为单位的整数保存，避免浮点误差；体重以斤保存为小数值。所有日期时间在本地时区展示和计算，数据库保存明确的日期或时间戳。

### 6.1 学期与课程

`Semester`：`id`、名称、开始日期、结束日期可选、是否当前学期、创建时间。

`Course`：`id`、`semesterId`、课程名、星期几、开始节次、结束节次、上课周规则文本、解析后的周集合、校区、地点、教师、课程编号、学分、备注。

周规则需要支持单周、双周、连续周、逗号分隔周和区间等常见表达。无法可靠解析的原文必须保留，并在预览中标记为需要确认。

### 6.2 日程

`ScheduleEvent`：`id`、标题、日期时间、提醒提前分钟数、提醒模式、是否按年重复、备注、创建时间、更新时间。

提醒模式至少包含消息提醒和闹钟提醒。闹钟事件记录是否已关闭，以支持响铃后由用户手动结束。

### 6.3 健康

`WeightRecord`：`id`、日期时间、体重斤、数据来源、备注。

`ActivityRecord`：`id`、日期时间、活动类型、步数、距离、持续时间、数据来源、原始记录标识。活动类型至少区分步行和跑步；字段允许某些来源只提供部分数据。

`MonthlyReport`：`id`、月份、体重趋势摘要、活动摘要、AI 建议文本、报告生成时间、建议来源和生成状态。

`HealthSettings`：目标体重、是否允许读取 Health Connect、是否允许读取传感器、报告生成偏好。

### 6.4 账单与预算

`Transaction`：`id`、发生时间、金额分、收支方向、分类、交易对方、来源文件、支付方式、交易类型、状态、商户订单号、订单号、原始文本、备注、导入批次、创建时间、更新时间。

`Budget`：月份、预算金额分、已触发的 50/70/90/110 百分比集合、更新时间。第一版每个月只设一个总预算，不做多分类预算。

`ImportLog`：批次 ID、文件名、来源类型、导入时间、总行数、成功行数、跳过行数、错误摘要。

### 6.5 配置

DataStore 保存当前学期 ID、显示偏好、默认提醒设置、预算默认值、同步开关、上次同步时间等非敏感配置。DeepSeek Key、WebDAV 用户名和密码等秘密由 Keystore 保护；日志中只显示脱敏后的服务名称或状态。

## 7. 关键业务流程

### 7.1 课表 PDF 导入

1. 用户选择本地 PDF。
2. 在后台解析文本和表格结构，识别课程名、星期、节次和周规则。
3. 显示解析预览，按课程列出已识别字段和警告。
4. 用户可以修改解析结果或取消。
5. 用户确认后，以事务方式保存学期和课程；已有课表只有在明确确认覆盖时才替换。
6. 保存后重新计算当前周课程并刷新首页、课表页和课程提醒。

解析器不依赖特定文件名。由于当前工作区没有真实课表 PDF，开发阶段先用合成 fixture 覆盖常见表格格式；拿到真实 PDF 后补充回归样本和设备验证。

### 7.2 日程与提醒

创建或编辑事件后，repository 写入 Room，通知调度器根据提醒时间注册或取消 AlarmManager 任务。

- 消息提醒使用通知渠道，按系统权限显示。
- 闹钟提醒使用精确闹钟和全屏/响铃流程，在系统允许范围内持续响铃，直到用户明确关闭。
- 设备重启、时区变化、时间变化和应用更新后重建未来提醒。
- 精确闹钟、通知和全屏通知权限都通过明确的设置引导获取；权限被拒绝时仍保存事件，并显示受限状态。
- 所有提醒调度都必须幂等，避免重复通知。

闹钟页面和前台响铃服务只在真正触发闹钟时启动。应用启动时不启动健康前台服务，也不做耗时的外部服务初始化。

### 7.3 健康记录与月报

用户可手动记录体重，目标体重保存在健康设置中。进入健康页面后，用户可以主动授权并读取 Health Connect；如果设备没有该能力，可使用设备传感器适配器或仅使用手动记录。

月报根据本地体重和活动数据计算：最近 30 天体重折线、周平均、月度变化、步行/跑步汇总和目标差距。AI 建议是可选增强：存在有效的 DeepSeek Key 且网络可用时生成；否则显示本地统计摘要，不阻塞报告查看。

AI 请求只发送生成建议所需的汇总数据，不发送不必要的原始记录或身份信息。请求失败、超时或 Key 无效时保留本地报告，并显示可重试状态。

### 7.4 账单导入与统计

1. 用户选择微信或支付宝 CSV/Excel 文件。
2. 解析器识别文件编码、表头、日期、金额、收支方向、交易对方、支付方式和状态。
3. 对无法识别的列显示映射或警告；原始行文本保留用于追溯。
4. 预览导入数量、跳过数量、重复风险和分类结果。
5. 用户确认后批量写入 Room，记录导入批次。
6. 账单页按月/周/年和日期范围统计收入、支出、分类、搜索结果和预算进度。

分类采用可解释的本地规则和可编辑结果，不依赖网络。重复导入使用来源、时间、金额、对方和订单号等字段建立去重指纹；疑似重复行在预览中提示，由用户决定是否导入。

预算阈值固定为 50%、70%、90%、110%。同一月份同一阈值只提醒一次；修改预算后重新计算阈值状态。预算提醒属于普通消息提醒，不影响账单保存。

### 7.5 备份与同步

本地备份将 Room 数据和必要配置导出为带版本号的快照。Nutstore 通过 WebDAV 作为可选远程存储。

第一版按单用户、主要单设备场景设计：

- 自动同步默认关闭，由设置中开启。
- 上传前生成完整快照，包含 schema 版本和更新时间。
- 远程上传使用临时文件再替换正式文件的方式，减少中断造成的损坏。
- 恢复操作必须由用户明确确认，并在覆盖前保留当前本地快照。
- 冲突不静默合并；发现远程和本地都在最近同步后发生变化时，显示两份快照的时间和大小，交由用户选择保留哪一份。
- 网络失败采用 WorkManager 重试，并在设置页显示最后同步状态。

## 8. 权限、后台和错误处理

Manifest 只声明实际功能需要的权限，并把敏感权限申请推迟到用户触发对应功能时。与第一版相关的权限包括通知、精确闹钟、活动识别/健康数据、前台服务和网络访问；具体权限以目标 Android SDK 和真实设备验证结果为准。

应用必须保证以下情况下仍能启动和浏览本地页面：

- 通知权限被拒绝。
- 精确闹钟权限未开启。
- Health Connect 不存在或用户拒绝授权。
- 网络不可用、DeepSeek Key 无效或 WebDAV 配置错误。
- 导入文件格式不支持、编码异常或字段缺失。
- 后台任务被系统延迟。

每种情况都使用页面内空状态、错误卡片或设置提示表达，不使用无上下文的崩溃或无限加载。启动流程只初始化本地数据库、配置和导航所需资源；耗时解析、同步、健康访问和报告生成均延后执行。

现有旧 APK 在测试模拟器上出现过长时间启动和健康前台服务超时，甚至触发系统无响应提示。新架构把健康初始化改为按需执行，并把启动路径纳入启动性能验收。

当前缺少真实课表 PDF、真实微信账单文件和真实支付宝账单文件。因此开发阶段使用合成 fixture；真实文件取得后必须补充导入回归测试，不能只凭合成样本宣称解析兼容。

## 10. 分阶段交付与验收标准

### 阶段一：工程基础与设计系统

建立 `com.daily.life` 工程、导航、主题、Quiet Sky 组件、Room/DataStore 基础和测试骨架。验收：可编译、可安装、可启动，五个页面可导航，启动不依赖网络或健康权限。

### 阶段二：首页与设置

完成首页聚合卡片、空状态和设置入口；设置支持学期开始日期、体重目标、月度预算、DeepSeek 配置、WebDAV 配置和权限状态。验收：配置本地持久化，首页数据随模块数据更新。

### 阶段三：课表模块

完成 PDF 选择、解析、预览、编辑、确认保存、周视图、当前周计算和课程提醒。验收：合成 fixture 可导入；未确认的解析结果不改变正式课表；课程在正确周和节次显示。

### 阶段四：日程模块

完成五页面中的日程页、创建/编辑/删除、考试/生日/小事快捷入口、消息提醒和闹钟提醒。验收：提醒按提前量触发；生日按年重复；设备重启后未来提醒可恢复；权限不足时事件仍可使用。

### 阶段五：健康模块

完成手动体重、目标体重、体重折线、活动摘要、Health Connect/传感器适配器入口和月报。验收：无健康权限时页面仍可用；本地统计可独立生成；AI 失败时仍有报告；不在启动阶段运行健康前台服务。

### 阶段六：账单模块

完成微信/支付宝 CSV/Excel 导入预览、分类、确认、单笔编辑、筛选搜索、统计和预算阈值。验收：导入前不写正式数据；金额以分计算；重复行有提示；50/70/90/110 阈值按月只提醒一次。

### 阶段七：同步、备份与发布验证

完成本地快照、WebDAV 上传/恢复、冲突提示、DeepSeek 可选建议、权限引导、启动与后台验证。验收：网络不可用不影响核心功能；秘密不明文落盘或进日志；debug APK 可安装；真实设备完成关键提醒和文件导入验证。

## 11. 外部验证材料与后续输入

以下材料不阻塞架构设计，但会影响解析兼容性和最终设备验收：

- 一份或多份真实课表 PDF。
- 一份微信账单 CSV/Excel 样本。
- 一份支付宝账单 CSV/Excel 样本。
- 如启用 AI：用户自己的 DeepSeek Key，由用户在应用设置中输入，不写入代码或提交到仓库。
- 如启用同步：Nutstore WebDAV 地址、用户名和密码，由用户在应用设置中输入。

真实账单文件如包含隐私信息，应先脱敏；脱敏必须保留表头、日期格式、金额格式、收支表达和典型字段，确保仍能用于解析测试。

## 12. 设计结论

Daily 第一版采用本地优先、原生 Compose、单模块分层架构，围绕五个页面组织四大功能。新包名和应用名与旧 APK 完全分离；Quiet Sky Unified 负责视觉方向，业务实现和数据模型由本设计文档重新定义。下一步在本设计文档获用户确认后，编写逐文件、可执行的实施计划，再开始工程实现。
