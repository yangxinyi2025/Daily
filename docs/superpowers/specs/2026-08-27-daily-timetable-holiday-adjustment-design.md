# Daily 课表节假日与调休校准设计

## 背景

PDF 课表保存的是“学期周次 + 星期 + 节次”的重复规则。当前 Daily 直接用学期开始日期和周次计算实际日期，因此法定节假日仍会显示普通课程，周末调休补课也不会显示。系统日历已经被用于读取节假日标记，本功能将把这些标记引入课表导入确认流程。

## 目标

- 不修改 PDF 解析出的原始课程规则。
- 在导入时读取学期范围内系统日历的节假日/调休事件。
- 让用户确认每个调休日期对应补哪一个课程日。
- 让课表展示和课程消息提醒使用完全相同的实际日期映射。
- 不内置节假日表，不根据周末或事件标题自行猜测补课来源。

## 非目标

- 不重新设计 PDF 解析格式。
- 不使用 Daily 自己的闹钟通道。
- 不把系统日历中普通日程、Daily 已创建的课程事件当作节假日或调休。
- 不在用户没有确认来源日期时自动复制课程。

## 用户流程

1. 用户选择 PDF，填写或确认学期名称与开始日期。
2. Daily 在拥有 `READ_CALENDAR` 权限时读取学期范围内的系统日历事件；学期结束日期缺省时按当前导入规则使用默认学期长度。
3. 导入预览中显示“节假日与调休校准”区域：
   - 节假日列出日期和系统日历标题，标记为“休”，无需逐条选择；
   - 调休/补班列出实际上课日期，提供“补哪一天”的选择；
   - 若标题/描述中含有“补周五”“补星期五”或明确日期，作为默认值，但用户仍可修改并确认；
   - 无法识别来源日期的调休项默认为空，必须选择后才能确认导入。
4. 用户确认导入后，Daily 保存调休映射到对应学期；取消导入不保存任何校准结果。
5. 后续查看周课表时，根据保存的映射和重新读取的系统日历标记生成实际日期课程。

## 日期映射规则

对一个实际日期生成一个 `ScheduleSlot`：

- 普通日期：使用实际日期的星期和当前学期周次。
- 节假日：该日期没有课程。
- 已确认调休日期：使用用户选择的来源星期/来源日期对应的课程规则，但课程实例日期仍是实际调休日期。
- 同一天同时存在“休”和“班”时，“班”优先，允许系统日历表达先休后补的特殊安排。
- 只有“班/调休”而没有用户确认来源时，不生成复制课程，并保留未完成校准提示。

周次仍沿用 PDF 与现有学期的名义周次，不因节假日重新编号；调休只改变该次课程落在哪个实际日期。

## 数据设计

新增学期级校准表，至少包含：

- `semesterId`
- `actualDate`
- `sourceDayOfWeek`（1-7）或明确的 `sourceDate`
- 系统日历事件摘要/来源标识，用于在系统日历内容变化后提示重新确认
- 创建或更新时间

主键为 `semesterId + actualDate`，同一调休日期只保留一个用户确认结果。替换同名学期时同步清理旧学期的校准数据；原始 `CourseEntity` 和 `CourseWeekEntity` 不变。

## 系统日历读取与解析

- 复用现有 `CalendarContract.Instances` 查询能力，但把“节假日/调休事件读取”抽成可被课表和月历共同使用的模型/读取器。
- 只识别标题或描述明确包含“节假日、放假、休息、休假、休、调休、补班、上班、班”等标记的事件。
- 解析来源时支持“补周一/补星期一”以及带月日的明确日期；无法解析则交给用户选择。
- 不通过日期是周六/周日、事件持续时长或常识推断补课来源。
- 没有读取权限或系统日历没有相关事件时，导入可继续，但显示“未读取到系统节假日/调休安排”，不伪造校准数据。

## 课表展示与提醒同步

- `TimetableViewModel` 按当前周读取校准后的 `ScheduleSlot`，节假日不挂载课程，已确认调休日期挂载来源课程。
- `RoomTimetableRepository.syncFutureCourseCalendarMessages` 调用同一个日期映射服务；跳过节假日，为调休日期生成课程消息提醒。
- 课程同步链接的唯一键需要包含实际日期，避免同一课程在名义周内出现正常日和调休日时互相覆盖。
- 重新导入、修改校准、修改节次时间时，先清理旧课程消息提醒，再按最新映射重建。

## 权限与失败处理

- 导入预览阶段需要读取系统日历，使用 `READ_CALENDAR`；写入课程消息提醒仍按现有日历写权限流程执行。
- 用户拒绝读取权限时不阻塞普通课表导入，但必须明确提示课表未进行节假日/调休校准。
- 日历查询失败只影响校准，不得导致原有 PDF 课程数据丢失。
- 检测到调休但来源日期未确认时禁止确认导入；不提供跳过入口，避免用户得到看似完整但实际错误的课表。
- 没有读取权限或系统日历没有相关事件时，允许普通导入，但必须显示未完成系统校准的明确提示。

## 测试要求

- 纯逻辑测试：普通日、节假日、已确认调休日、同日“休/班”优先级、未确认调休不复制。
- 导入流程测试：系统日历事件能生成校准项；默认解析值可修改；未完成必选项不能确认；确认后持久化到学期。
- 课表展示测试：节假日隐藏课程、调休日显示来源课程，名义周次和 1-12 节次不变化。
- 提醒同步测试：课程提醒日期与课表日期一致；节假日不生成提醒；调休日生成实际日期提醒；链接键不覆盖不同实际日期。
- 权限/查询失败测试：无权限时可继续普通导入并显示未校准提示。

## 验收标准

以用户提供的学校调休安排为例：用户导入 PDF 后能看到每个“班/调休”日期，并选择“补周几”；确认后，国庆等“休”日期不显示普通课程，周末补课日期显示对应课程，课程消息提醒也落在周末实际日期。整个过程不依赖 Daily 自己的闹钟服务，也不硬编码某一年的节假日。
