# Daily 真正闹钟设计

## 目标

当用户在 Daily 中为日程选择“闹钟提醒”时，Daily 必须在用户正常返回桌面、锁屏或息屏后，于设定时间播放闹钟铃声与震动，并显示可关闭的锁屏闹钟界面。

## 边界

- “消息提醒”继续由系统日历承载。
- “闹钟提醒”由 Daily 的 Android 精确闹钟链路承载，不能依赖 `CalendarContract.Reminders.METHOD_ALARM`。
- 两类日程均同步一个可查看的事件到系统日历；闹钟类事件不在系统日历创建提醒，避免日历的提醒规则覆盖或误导 Daily 的真正闹钟。
- 手动“强制停止”Daily 是 Android 对所有第三方应用的终止语义，会取消其后续闹钟；正常返回桌面、锁屏和息屏必须支持。

## 用户流程

1. 用户在 Daily 创建或编辑日程，选择“闹钟提醒”与提前分钟数。
2. Daily 检查“闹钟和提醒”特殊权限；未获准时打开系统授权页，并在返回后重新登记闹钟。
3. Daily 用 `AlarmManager.setAlarmClock` 与 `PendingIntent` 登记到点广播，保存后的状态明确显示下一次触发时间。
4. 到点广播启动前台铃声服务，并发布高优先级、全屏闹钟通知；锁屏时弹出 Daily 闹钟界面。铃声使用系统 `TYPE_ALARM` 音量流并振动。
5. 用户在锁屏页或通知中关闭闹钟，服务停止铃声和震动，通知取消。
6. 重启、时区变更、手动修改系统时间或应用更新后，开机接收器重新登记未到期的日程闹钟。

## 组件与职责

- `AndroidReminderScheduler`：只负责精确闹钟的注册、取消和重登记；消息提醒不再由它执行。
- `ReminderReceiver`：从精确闹钟广播读取稳定的日程 ID、标题和备注，启动铃声服务与全屏通知。
- `AlarmRingtoneService`：以前台服务运行，播放闹钟流铃声、振动，并保持闹钟通知直到用户关闭。
- `AlarmActivity`：锁屏可见、点亮屏幕，提供唯一的“关闭闹钟”操作。
- `ReminderPermissionCoordinator`：检查并请求通知、精确闹钟和全屏通知所需的系统设置，向日程页返回可理解的状态。
- `BootReceiver`：在系统事件后以异步方式重登记未来闹钟。

## 权限与平台约束

- `SCHEDULE_EXACT_ALARM`：用户必须在系统“闹钟和提醒”中允许 Daily；保存闹钟时若未允许，不能伪报成功。
- `POST_NOTIFICATIONS`：用于显示闹钟通知与全屏入口；首次设置闹钟时请求。
- `FOREGROUND_SERVICE` 与 `FOREGROUND_SERVICE_MEDIA_PLAYBACK`：用于到点稳定播放铃声。
- `USE_FULL_SCREEN_INTENT`：用于锁屏显示关闭闹钟的界面；若系统不授予，仍保留铃声与高优先级通知。
- Android 公共日历 API 仅可靠执行默认／通知提醒，不能替代以上闹钟链路。

## 数据与日历同步

- Daily 本地 `ScheduleEvent.reminderMode` 继续是唯一的提醒模式来源。
- 对闹钟日程：写入 Daily 的 `AlarmManager`；镜像至系统日历时只写事件信息和说明“由 Daily 闹钟提醒”。
- 对消息日程：写入系统日历事件及其通知提醒。
- 删除或把闹钟改成消息时，先取消对应的 `PendingIntent`，再同步系统日历。

## 失败处理与自检

- 未授予精确闹钟权限：显示“尚未允许 Daily 设置闹钟和提醒”，不显示“已设置”。
- 注册异常：保留日程，但显示“闹钟未登记”；不创建误导性的系统日历提醒。
- 自检页显示精确闹钟授权状态、通知授权状态、全屏通知状态、下一个 Daily 闹钟时间和最近一次到点接收记录。

## 验证

- 单元测试覆盖：闹钟模式选用 `setAlarmClock`、消息模式不进入 Daily 铃声链路、权限拒绝不登记、删除取消登记、重启重登记。
- Robolectric 测试覆盖：接收器创建正确的前台服务与闹钟通知、关闭操作停止服务。
- 设备验收覆盖：设置 2 分钟后的 Daily 闹钟，按主页键／锁屏，确认到点铃声、震动和锁屏关闭入口；再验证消息提醒不会触发 Daily 铃声。
