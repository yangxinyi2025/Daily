# Daily 中国节假日、调休与课表校准设计

## 背景

Daily 的日历和课表都需要判断一个实际日期是工作日还是休息日。中国节假日安排还包含工作日调休：法定节假日可能落在工作日，周末也可能被安排补班。仅依靠星期几无法得到正确的实际日期安排；仅依靠单个系统日历事件又无法稳定支持同步、缓存、冲突处理和用户修正。

当前课表已经具备系统日历特殊日期读取和“实际日期 → 课程来源星期”的基础能力。本设计把节假日数据来源、调休规则、手动修正和课表行为统一起来，并与已有的课程消息提醒日期映射共用同一套规则。

本设计补充并扩展 `docs/superpowers/specs/2026-08-27-daily-timetable-holiday-adjustment-design.md`：保留其“课表展示与课程提醒必须使用同一实际日期映射”的原则，但将数据来源从“仅系统日历”扩展为 ICS、系统日历和手动修正的多来源模型。

## 目标

- 为日历、课表和课程提醒提供一个统一的实际日期规则服务。
- 支持内置推荐的中国节假日 ICS 订阅源。
- 支持用户添加、修改和删除自定义 ICS 订阅源。
- 支持读取手机系统日历中的节假日和调休事件作为补充来源。
- 支持每日后台同步、打开 App 时检查和用户手动立即同步。
- 支持无网络时使用本地缓存，单个来源失败不影响其他来源。
- 使用确定的来源优先级解决同一天的冲突。
- 支持对单天或日期范围手动设置休息/上班状态。
- 支持对课表单天或日期范围手动设置有课/无课。
- 对没有说明“补哪一天”的调休事件，不阻塞课表导入，不自动复制课程，并显示待校准状态。

## 非目标

- 不把某一年节假日表硬编码为唯一数据来源；内置的是可替换的 ICS 订阅配置。
- 不把普通系统日历事件、Daily 自己创建的课程事件或生日事件误判为节假日。
- 不根据“周六/周日”单独猜测全国调休安排。
- 不修改 PDF 解析出的学期周次、星期和节次原始规则。
- 不把全国调休直接等同于学校课程安排；学校课程仍允许按日期手动修正。
- 不恢复或扩大与节假日规则无关的健康、账单或其他模块范围。

## 核心概念

### 日期状态

每个实际日期最多生成一个合并后的日期状态：

- `REGULAR_WORKDAY`：普通工作日。
- `REGULAR_REST_DAY`：普通休息日，通常是周末。
- `HOLIDAY_REST`：节假日休息日。
- `MAKEUP_WORKDAY`：调休补班日。

日期状态还保存标签、来源、来源事件标识、置信度和更新时间。`MAKEUP_WORKDAY` 和 `HOLIDAY_REST` 是对普通星期规则的覆盖，而不是修改 `LocalDate` 或名义周次。

### 课表覆盖

课表行为与通用日期状态分开保存：

- `FOLLOW_CALENDAR`：按统一日期规则计算。
- `HAS_CLASS`：当天有课，覆盖自动的无课判断。
- `NO_CLASS`：当天无课，覆盖自动的有课判断。

调休补班还需要一个课程来源星期，例如实际周六补周五。这个“实际日期 → 课程来源星期”的学期级校准与“有课/无课”覆盖分开保存，避免把社会工作日和学校课程日混为一谈。

## 数据来源与优先级

### 来源

1. 手动修正：用户针对日期或日期范围设置的日期状态和课表状态。
2. 内置推荐 ICS：默认启用，可在设置中查看和更新。
3. 自定义 ICS：用户可以添加多个地址，并单独启用、停用或删除。
4. 手机系统日历：在拥有 `READ_CALENDAR` 权限时读取，作为补充来源。
5. 普通周末规则：没有任何特殊来源时，使用星期规则。

### 冲突优先级

同一天存在多个来源时，按以下顺序生成最终日期状态：

```text
手动日期状态 > ICS 订阅 > 系统日历 > 普通周末规则
```

在同一优先级内（包括多个 ICS 源之间），若同时出现休息和补班，`MAKEUP_WORKDAY` 优先于 `HOLIDAY_REST`，以支持“先放假、后补班”或来源重复的情况；同类状态合并标签和来源，不再用同步时间随机覆盖。合并结果保留所有来源摘要，便于在详情页解释为什么得到该状态。

未知、含义不明确或无法解析日期的事件不能改变最终日期状态，只能进入“待校准/未识别来源”提示。

## ICS 配置与解析

### 配置

设置页提供节假日订阅区域：

- 显示内置推荐源的名称、启用状态、最后同步时间和最近错误。
- 允许添加自定义 ICS 地址。
- 对自定义源提供启用/停用、立即同步和删除操作。
- 不把完整 ICS 内容展示为用户必须理解的配置；用户只需要提供地址。

内置推荐地址必须通过可变配置保存，不能散落在多个业务类中。后续更换地址不应要求修改日期映射逻辑。

### 解析

ICS 读取至少支持：

- `VEVENT` 的 `DTSTART`、`DTEND`、`SUMMARY`、`DESCRIPTION`。
- 全天事件和跨天事件；结束日期按 ICS 全天事件的排他结束语义处理。
- 事件标题或描述中明确表示“放假、休息、节假日、调休、补班、上班”等含义。
- “补周一”至“补周日”和“补星期一”至“补星期日”。
- 能识别明确日期时，保存来源日期或来源星期；无法识别时保留未知来源。

解析器是纯逻辑组件，不直接访问网络或数据库。单个坏事件不能使整个订阅失败；错误事件被跳过并记录解析统计。

## 系统日历读取

系统日历读取复用现有 `CalendarContract.Instances` 能力，但通过共享模型进入日期状态合并层。读取时：

- 只查询请求的日期范围。
- 读取开始时间、结束时间、标题和描述。
- 忽略 Daily 已创建的课程提醒和普通日程事件。
- 使用明确关键词识别节假日/调休，无法识别的事件不参与判断。
- 没有 `READ_CALENDAR` 权限时返回空结果和权限状态，不抛出异常。
- 查询失败只影响系统日历来源，不影响 ICS、本地缓存或课表导入。

系统日历不是唯一真相；用户拒绝权限时，ICS 和本地数据仍然可用。

## 同步与缓存

### 触发方式

- 每天后台同步一次所有已启用 ICS 源。
- Daily 启动或回到前台时检查是否需要同步。
- 设置页提供“立即同步”。
- 系统日历在读取具体日期范围时按需查询，不复制到网络订阅缓存。

后台任务使用现有 Android 后台任务基础设施，不能阻塞 App 启动或课表导入。同步任务需要幂等：同一个源重复同步不会产生重复日期记录。

### 网络失败与缓存

每个 ICS 源保存：

- 地址和启用状态；
- 最近成功同步时间；
- 最近错误信息；
- `ETag`/`Last-Modified` 等可用的条件请求信息；
- 最近一次成功解析的事件和日期结果。

网络失败、HTTP 错误或解析失败时，保留该源最近一次成功缓存，并在设置页显示过期/错误状态。只有用户删除源或明确清空缓存时才删除其数据。合并服务仍然可以使用其他源和手动修正。

## 手动日期修正

用户可以在日历详情或设置中选择：

- 单个日期；
- 一段连续日期。

批量操作实际保存为每个日期一条记录，而不是保存一个不可解释的隐式范围。用户可以把选中日期设为“工作日”或“休息日”，也可以撤销修正恢复自动结果。

手动日期修正覆盖 ICS、系统日历和周末默认规则。记录包括日期、目标状态、备注、创建时间和更新时间。

## 课表日期映射

### 默认规则

对一个实际日期生成课程槽位时：

1. 若存在 `NO_CLASS`，不生成课程。
2. 若存在 `HAS_CLASS`，允许生成课程；课程来源按已确认的来源星期，否则按实际星期。
3. `HOLIDAY_REST` 默认不生成课程。
4. `MAKEUP_WORKDAY` 使用已确认的课程来源星期，把来源星期的课程放到实际补班日期。
5. 普通日期按实际星期使用 PDF 的课程规则。
6. 调休事件没有来源星期且没有手动课程来源时，不自动复制课程，标记为“待校准”。

实际日期仍然是课程实例的日期；学期名义周次不因节假日重新编号。课表 UI 和课程消息同步必须调用同一个纯逻辑映射器。

### 导入流程

PDF 导入预览在合法学期日期范围内加载合并后的日期状态：

- 节假日显示日期和标签；
- 调休日显示实际日期、来源信息和“补哪一天”选择；
- 已从 ICS 或系统日历解析出来源星期时预填，但用户可以修改；
- 只有“调休上班”而没有来源星期时，显示“待校准”；
- 待校准不会阻塞 PDF 导入；
- 导入完成后，待校准日期不复制课程，并在课表中保留明确提示；
- 用户之后可以选择来源星期或设置有课/无课，保存后重新计算课程和提醒。

导入替换已有学期时，保留用户明确的手动修正，重新计算来自订阅和系统日历的自动结果；对于已经不存在的日期来源，显示需要复核的状态，不静默删除用户修正。

## 日历界面

月历和日期详情使用最终合并状态：

- 普通工作日、普通休息日、节假日和补班日有可区分的视觉标记；
- 显示手动修正标记；
- 点击日期可以查看来源摘要和当前优先级结果；
- 对有课/无课修正提供进入课表校准的入口；
- 同一天存在多个来源时不重复绘制多个冲突标记，只显示最终状态，并在详情中解释来源。

现有日历页面的整体视觉语言和底部导航保持不变，只增加状态信息和必要的修正入口。

## 失败处理与权限

- ICS 没有网络：使用本地缓存，并显示最后成功同步时间。
- ICS 地址无效或内容无法解析：保留旧缓存，显示源错误，不清空现有有效日期。
- 系统日历权限被拒绝：继续使用 ICS、本地缓存和手动修正，并提示系统日历未接入。
- 所有来源都不可用：使用普通周末规则，且不伪造节假日数据。
- 调休来源不明确：不阻塞导入、不复制课程，显示待校准。
- 数据库迁移失败或缓存损坏：不影响原始 PDF 课程规则，回退到无特殊日期的普通课表，并记录可读错误。

## 数据模型建议

在现有学期调休校准表基础上，增加或拆分以下职责：

- `HolidayCalendarSourceEntity`：订阅源地址、类型、启用状态、同步状态和错误信息。
- `HolidayCalendarEventEntity`：源事件的日期范围、标题、描述摘要、解析结果和来源标识。
- `CalendarDayOverrideEntity`：用户对日期状态的单日修正。
- `SemesterCalendarAdjustmentEntity`：学期内实际日期到课程来源星期的确认结果。
- `SemesterClassOverrideEntity`：学期内实际日期或批量展开后的有课/无课修正。

所有日期使用 `LocalDate` 和现有时区转换规则；事件的原始时间信息保留来源时区或标准化后的 `Instant`，避免跨时区导致日期偏移。来源记录需要可追溯，但业务映射器只依赖规范化后的纯模型。

## 测试策略

### 纯逻辑测试

- 普通工作日和普通周末状态。
- ICS 节假日覆盖普通工作日。
- ICS 补班覆盖节假日。
- ICS 事件识别“补周五”和“补星期五”。
- 手动日期修正覆盖 ICS、系统日历和周末默认规则。
- 调休来源未知时标记待校准。
- 已确认补班日期使用来源星期生成实际课程。
- 课表 `HAS_CLASS`/`NO_CLASS` 覆盖自动结果。
- 课表显示和课程提醒使用同一个实际日期映射。

### ICS 与同步测试

- 全天单日和跨日事件解析。
- 排他结束日期处理。
- 多源合并和来源优先级。
- 同源重复同步幂等。
- 条件请求和缓存回退。
- 单个源失败不影响其他源。
- 无网络或无权限时的状态提示。

### 数据库与 UI 测试

- 源配置、启停、删除和同步状态持久化。
- 日期覆盖单日和批量展开、撤销。
- 学期校准和课程覆盖的替换、删除、迁移。
- 导入预览显示节假日、补班和待校准状态。
- 待校准不阻塞导入且不复制课程。
- 日历详情显示最终状态和来源解释。

### 验收标准

以一个包含工作日节假日和周末补班的中国节假日安排为例：用户打开 Daily 后能看到同步状态；日历显示节假日和补班；导入 PDF 时调休日可以选择补哪一天；没有来源星期的调休不会阻塞导入但不会错误复制课程；用户完成校准后，课表和课程消息提醒都落在实际补班日期；用户的手动日期或有课/无课设置始终覆盖自动来源。

## 实施顺序建议

1. 抽象统一的日期状态、来源和合并器。
2. 增加 ICS 解析器、源配置和本地缓存。
3. 将系统日历读取接入统一合并器。
4. 扩展现有学期调休校准和纯逻辑课程日期映射。
5. 在导入预览和日历详情中加入待校准、来源和手动修正 UI。
6. 让课程消息同步复用同一映射器。
7. 完成后台同步、权限失败、缓存回退和 APK/模拟器验证。
